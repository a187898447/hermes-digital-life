# 记忆系统对比：本地记忆宫殿 vs 腾讯云 Agent Memory

日期：2026-11-04
对象：
- 本地实现：`digital_life/memory.py`（记忆宫殿：按日分片 JSONL + FTS5 索引 + 衰减/注意力排序 + 日记）
- 对照：TencentDB Agent Memory（腾讯云数据库 Agent Memory，三层记忆引擎）
来源：腾讯云文档 <https://cloud.tencent.cn/document/product/1813/132100>、产品页 <https://landscape.jimmysong.io/zh/projects/tencentdb-agent-memory/>

## 一句话对照

腾讯云是「企业级记忆服务」：短期记忆管窗口、长期记忆做四层蒸馏、团队记忆做资产化与权限，靠混合检索（关键词+向量+RRF）与白盒溯源支撑多人多 Agent。
我们是「单机单 profile 的轻量记忆」：逐轮捕获 + 按日分片 + 字面检索 + 衰减打分 + 日记，零依赖、可离线、可审计到文件。

## 维度对比

| 维度 | 本地记忆宫殿 | 腾讯云 Agent Memory | 评价 |
|---|---|---|---|
| 形态 | 本地 JSONL 事件日志 + SQLite FTS5 索引 | 托管服务：向量库 + 文件存储 + Memory Hub | 我们胜在零成本/隐私；它胜在规模与多人 |
| 记忆分层 | 原始 turn、journal 两类；无原子事实层、无核心记忆层 | 四层金字塔：原始对话 → 原子记忆 → 场景记忆 → 核心记忆 | 我们缺中间两层，日记是「场景+核心」的混合体 |
| 写入 | 每轮自动捕获 + 模型显式 memory_write；去重、按会话计配额 | 短期记忆窗口 → 任务结束自动提炼入长期层 | 我们捕获密度高；它提炼质量高 |
| 检索 | FTS5 字面（中文 bigram/英文 token）+ LIKE 回退 + BM25；打分=相关度/权重/新近/注意力 | 关键词 + 向量语义 + RRF 融合 | 我们同意异、跨表述召回弱；它语义召回强 |
| 排序 | 0.40 相关 + 0.20 权重 + 0.15 新近 + 0.25 相关×注意力；空查询用权重/新近/注意力 | RRF 融合 + 分层权重 | 接近，但缺语义向 |
| 遗忘 | archived 归档（不删文件）+ 衰减 effective_weight；P2 才做冷层摘要 | 冷数据卸载到持久层 + 分层提炼（原始层保留） | 我们「归档不压缩」，长期会越积越多 |
| 溯源 | 每条有 id、source_session_id；journal 无向下链接 | 每条结论保留原始来源链接，可逐层下钻 | 我们做得浅，这是最值得补的一项 |
| 隔离 | profile 级 + chat_id 级（QQ 私聊/群） | 团队/成员/Agent 多级，Owner + 显式共享 | 我们够用但不支持团队复用 |
| 部署/成本 | 本地文件，免费，离线可用，随 profile 备份 | 云服务，按量计费，需网络与账号 | 场景不同，不可直接替代 |
| 隐私 | 数据不出本机 | 数据上传云端（企业可私有化） | 对 QQ 私人聊天，本地是硬优势 |
| 可维护性 | 一个 py 文件 ~600 行，事件可重放，索引可重建 | 平台化，运维由云承担 | 我们改起来快；它稳定但要学 API |

## 腾讯方案值得借的点

1. **原子记忆层**：把每轮 turn 蒸馏成 1–3 条带来源 id 的原子事实（谁、何时、说了什么结论），再让 journal 引用这些事实。
   - 收益：检索粒度更细；日记可下钻；「她说记得」不再是一整段聊天记录。
   - 代价：每晚一次模型调用；需要新的 kind 与去重键。
2. **混合检索（关键词 + 向量 + RRF）**：先接一个本地小 embedding（如 bge-small）或云 API，把 FTS5 与向量结果做 RRF。
   - 收益：中文同义、口语改写召回明显提升（这是当前最大短板）。
   - 代价：多一个索引与依赖；需处理模型不可用时的降级。
3. **白盒溯源链**：journal → 原子事实 → 原始 turn 三级链接，`memory_recall` 返回 `sources`。
4. **冷层摘要**：对 archived 且 30 天未访问的条目做一次摘要合并，原始文件保留，只压缩检索面。
5. **团队/资产模型**：如果未来要多个人格共享经验，再引入 Owner + 显式共享，不必现在做。

## 我们不该照搬的

- 短期记忆的「窗口管理/冷数据卸载」：宿主（Hermes）已经做了上下文裁剪，插件再管会打架。
- 云端托管与多租户权限：单机 QQ 机器人场景用不上，还会把私聊内容送出本机。
- 四层全量蒸馏：每一层都要模型调用，成本高；对「小鲸鱼」这种日常闲聊，日记 + 原子事实两层足够。

## 建议路线

- P0（低成本、收益最大）：原子事实抽取（每晚一次）+ journal 引用事实 + recall 返回 sources。
- P1：向量检索与 RRF 融合（可先只对 fact/journal 建向量，turn 不建）。
- P2：冷层摘要与 include_cold 的默认收敛。
