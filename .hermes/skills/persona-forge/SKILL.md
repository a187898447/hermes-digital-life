# persona-forge：思维 skill → SOUL.md

## 输入

1. 源文件：女娲产出的人物 skill（通常是 `~/.hermes/skills/personas/<名字>/SKILL.md`）
2. 角色名（profile 名，与 SOUL.md 里的自称可以不同）
3. 一句话关系设定（用户与角色的关系、称呼）
4. 可选：目标 profile（默认 `~/.hermes/profiles/<角色名>`，default profile 是 `~/.hermes`）

缺 2/3 时先问，不要替用户编关系。

## 步骤

1. 读源文件，只提取：心智模型、决策启发式、表达 DNA、反模式、诚实边界。忽略经历、作品清单、引用金句。
2. 用仓库里的 `personas/SOUL.template.md` 作骨架，逐段填充。
3. 表达 DNA 必须写出**正例 + 反例**各一句；没有就从源文件里找原话改写。
4. 关系与称呼必须具体（叫名字、叫"你"、还是叫外号），不写"友好自然"这类空话。
5. 反模式改写成人称："他不下结论" → "你不下没有依据的结论"。
6. 安全边界原样保留模板里的四条，不删不改。
7. 全篇控制在 40–80 行；超过就删修饰，保留行为倾向。
8. 写入目标 profile 的 `SOUL.md`；profile 不存在时提示先跑 `install.sh`，不要自己建目录。
9. 报告：写入了哪些段落、删掉了哪些、还有哪一段需要用户补（通常只有关系设定）。

## 硬规则

- 不虚构源文件里没有的事实、经历、关系。
- 不把女娲的"这个人不会做 X"直接保留为第三人称，统一改成"你"。
- 不写"你会主动联系用户"——主动消息由宿主 cron/send_message 决定，人格不承诺。
- 不覆盖或弱化安全边界。

## 产物检查

```bash
hermes -p <角色名> chat
# 输入一句日常问题，确认：称呼对、语气像、不说教、不知道会承认
```
